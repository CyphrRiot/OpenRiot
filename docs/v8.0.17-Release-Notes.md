# OpenRiot v8.0.17: Groundhog Day, Cancelled

> _"Every morning the alarm goes off, Sonny and Cher play, and
> the same dialog asks if you are running LibreOffice for the
> first time. You are not. You have never been. The machine
> just keeps reading a version string that says otherwise."_
> -- The OpenRiot Crew, v8.0.17

---

## Release Overview

The LibreOffice welcome wizard would not stay dead.

The dark scheme shipped. The Paper Mono defaults shipped. The
wizard came back anyway, every launch, like a morning radio
host who has not been told the joke ended.

The culprit was a version check, not a preference. This release
fixes that, and the welcome dialog finally learns to stay gone.

---

## The Version That Wasn't There

LibreOffice decides "first run" twice. Once from
`FirstRun`, which we set to `false`, and again from
`ooSetupLastVersion`. If the stored version is older than the
running version, it raises `FirstRun` back to `true` and shows
the wizard. That second check is why the dialog kept coming
back after every clean install.

The bundled profile never set `ooSetupLastVersion`, so
LibreOffice read it as `0.0`, compared it against `26.8`, and
concluded the machine had just upgraded from the stone age.
The welcome dialog opened. Sonny and Cher played.

The profile now sets:

```
/org.openoffice.Setup/Product
  ooSetupLastVersion = 99.0
```

A future version means the comparison never fires. The dialog
stays dismissed, and the first-run flag stays false.

---

## The Full Profile

The bundled `registrymodifications.xcu` now carries the whole
contract for a dark, mono LibreOffice:

| Key | Value |
|-----|-------|
| `ColorScheme` | `COLOR_SCHEME_LIBREOFFICE_DARK` |
| `UseOnlyWhiteDocBackground` | `false` |
| `SymbolStyle` | `breeze_dark_svg` |
| `FirstRun` | `false` |
| `ooSetupInstCompleted` | `true` |
| `WhatsNewDialog` | `false` |
| `ooSetupLastVersion` | `99.0` |
| Writer Standard/Heading/etc | `Paper Mono` |

One file. No wizard. Dark page, Paper Mono type, and the Breeze
Dark icon set, on the first launch and every launch after.

The trade is the same one from v8.0.16: the profile overwrites
on install. The tradeoff on `ooSetupLastVersion = 99.0` is that
LibreOffice's own version-migration prompts are also skipped,
which is the point.
