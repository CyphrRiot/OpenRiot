## Release Overview

OpenRiot 8.0.2 is a maintenance release for the setup path. It does
not change the desktop. It changes how much work setup does before it
knows whether work is needed.

The package update was the biggest offender. Every `setup.sh` run
executed `pkg_add -Iu`, which scans the full package index and can
take up to an hour even when every pinned package is already installed.
The installer now asks whether the installed packages match the pins
first. If they do, the update is skipped. If they do not, the full
update runs once.

The release also finishes the setup output cleanup: package messages
now use the same `[INFO]` and `[WARN]` prefixes as the rest of the
installer, and the documentation no longer tells users to run
`pkg_add -u` when setup already does it.

**Total changes: one fast package check, one conditional update, and
documentation that stops repeating the work.**

---

## Ask the Disk First

The old flow was unconditional:

```sh
pkg_add -Iu
```

That command is correct after a base upgrade. It is wasteful on the
next run. Version matching scans the package index, resolves
dependencies, and reports every package before deciding most of them
are already current.

The new command is silent and local:

```sh
openriot --packages-current
```

It compares `install/packages.yaml` against `pkg_info` and exits:

- `0` when every pin is installed at the exact version
- `1` when any pin is missing or different

Setup now runs the full update only when the check fails:

```sh
if ! run_openriot --packages-current "$LOG_FILE"; then
    run_openriot --pkg-update "$LOG_FILE"
fi
```

The first 8.0 setup still runs the full update. The next setup on the
same release skips it. An 8.1 release changes the pins, so the check
fails once and the update runs again.

Somewhere a vendor is reinstalling the same packages every launch and
calling it a feature. We ask the disk first.

## The Package Line Learns Its Prefix

The update message was the only line in setup without a prefix:

```text
Updating packages from OpenBSD 8.0 stable...
```

It now matches the rest of the output:

```text
[INFO] Updating packages from OpenBSD 8.0 stable...
[WARN] This can take up to an hour.
```

The warning is honest about the worst case. The shorter message fits a
normal terminal without wrapping.

---

## The Manual Tells the Truth

The upgrade guide had three corrections:

- **Backup is optional.** The heading now says so, and the text says
  skipping it removes the only rollback path.
- **The 1.1G figure stays.** That is OpenBSD's official `/usr`
  requirement. The sets are smaller, but the guide's margin is the
  number to use.
- **`pkg_add -u` is not a user step.** Setup runs `pkg_add -Iu` before
  installing pins. The manual now says so instead of asking the user
  to repeat it.

`sysmerge` remains recommended. `fw_update` remains optional.
`pkg_add -u` remains the fallback when setup cannot complete.
